# 찌봄 — 입질 알림 (카메라 · 진동)

찌봄은 **찌를 대신 지켜보는** 앱입니다. 폰 카메라로 찌를 보거나(카메라 감지), 낚싯대에 단 폰의 센서로 떨림을 느껴(진동 감지) 입질이 오면 큰 소리와 진동으로 알려 줍니다.

- 웹앱(PWA)과 안드로이드 앱이 같은 화면·같은 판정 로직을 씁니다.
- 영상과 센서 데이터는 **폰 안에서만** 분석합니다. 서버로 보내지 않고, 분석 도구나 광고 SDK도 없습니다.
- 고전적인 컴퓨터 비전(색 마스크·연결 요소·블록 매칭)과 신호 처리로 동작합니다. 학습된 AI 모델은 쓰지 않으며, 그렇게 표시하지도 않습니다.

## 바로 써 보기

### 웹 (Android Chrome 권장)

배포 주소를 열거나, 로컬에서 정적 서버로 엽니다. ES 모듈을 쓰므로 `file://`로는 열리지 않습니다.

```bash
cd jjibom-webapp
python3 -m http.server 8080      # http://localhost:8080
```

- 카메라 없이 보기: **데모** 버튼(가상 낚시터가 실제 추적 파이프라인을 그대로 탑니다)
- 폰에서 실제 카메라·센서를 쓰려면 HTTPS 배포가 필요합니다(Vercel 설정 포함: 루트 `vercel.json`).

### 안드로이드 앱 (화면을 꺼도 진동 감시)

1. GitHub → **Actions** → 최신 **Android APK** 실행 → Artifacts의 `jjibom-debug-apk` 다운로드
2. 압축을 풀어 `app-debug.apk`를 폰에 옮기고 설치(“출처를 알 수 없는 앱” 허용 필요)
3. Android 7.0(API 24) 이상. 디버그 서명이라 스토어 배포용은 아닙니다.

## 쓰는 법

### 카메라 감지 — 찌가 화면에 또렷할 때

1. 폰을 삼각대·거치대에 **단단히 고정**하고 **카메라 켜기**
2. 화면에서 찌 끝(빨강·주황·형광)을 **한 번 톡** — ‘여러 찌 동시 감시’를 켜면 최대 4개
3. 2~3초 동안 평소 물결을 익힙니다(폰을 건드리지 마세요)
4. **감시 시작** → 잠김·솟음·토독을 구분해 알람

찌를 잠깐 놓치면 알람 대신 “찌를 놓쳤어요”로 알리고, 다시 찾으면 기준을 새로 잡습니다. 카메라가 흔들리는 동안엔 알람을 보류합니다.

### 진동 감지 — 밤낚시·원투처럼 찌가 안 보일 때

1. 폰을 낚싯대에 거치대·커플러로 고정(안전줄 권장)
2. **보정하고 감시 시작** → 6초 동안 평소 흔들림을 익힘
3. 강한 당김 / 토독거림 / 반복 진동을 알람. 폰을 만지면 입질이 아니라 “재안정화”로 처리

### 알람 뒤

알람 화면에서 **알람 끄기** → “입질 맞아요 / 오탐이에요 / 모르겠어요”를 남기면 기록 탭의 적중률에 쌓입니다. 카메라 감지는 오탐이 잦으면 스스로 조금 둔감해집니다.

## 화면 디자인 — “Still Water”

밤의 호수를 캔버스로 삼았습니다. 첫 화면은 살아 있는 호수 장면(별·능선·물결·빛나는 찌)이고, 조작부는 그 위에 떠 있는 유리 패널입니다.

- **색**: 찌 끝의 불빛 **ember `#ff6a3d`**가 브랜드 색, 살아서 감시 중인 것은 **lume `#8df5c8`**. 알람은 화면 전체가 붉게 차오르는 풀스크린.
- **글꼴**: Pretendard Variable을 앱이 쓰는 글자만 남겨 자체 호스팅(106 KB, OFL). 계기 숫자는 가는 두께, 헤드라인은 두 톤(둘째 줄이 물속으로 가라앉듯 흐려짐). 한글에는 자간을 벌리지 않습니다.
- **감시 화면**: 카메라가 주인공. 조작 덱은 점수·파형·한 줄 계기·버튼 하나로 압축, 상단 칩이 “감시 중 · 경과 시간”을 보여 줍니다. 진동 모드는 큰 숫자와 실시간 지진계 파형.
- **레이아웃**: 폰 세로는 하단 덱 + 독, 태블릿 가로·데스크톱·폰 가로는 왼쪽 레일 + 오른쪽 덱 컬럼. 야간(적색) 화면, 집중 모드(독 숨김), 동작 줄이기 설정을 지원합니다.
- **세부**: 찌를 누르면 모서리 괄호가 조여 들며 고정, 보정 링, 감시 중 호흡하는 후광. 토스트가 뜨면 겹치는 정보는 잠시 비켜섭니다.

## 정확도와 안정성

카메라:

- **Blob 추적** — 색 평균이 아니라 연결 요소로 찌를 찾아, 떨어진 같은 색 물체를 합치지 않습니다.
- **흔들림 처리** — 전체 화면 휘도 차이로 흔들림을 감지해 알람을 보류하고, 멈추면 찌 위치를 전수 블록 매칭(±8 px)으로 다시 맞춘 뒤 기준을 새로 잡습니다.
- **크기 정규화** — 임계값을 찌 높이의 배수로 계산해 줌·거리·해상도에 둔감합니다.
- **상태 머신** — 추적/입질 가능/놓침/회복/알람을 분리해 한두 프레임 놓침이 입질로 둔갑하지 않습니다.

진동:

- **샘플링 속도 무관** — 필터를 시간 상수(ms)로 정의해 20 Hz 기기와 60 Hz 기기가 같은 판정을 냅니다. 보정도 실제 샘플 간격을 봅니다.
- **토독 묶음** — 650 ms 안에 450 ms 이하 간격으로 이어진 튐만 한 번의 토독으로 봅니다.
- **접촉 판별** — 필터 전 원신호 크기와 기울기 변화로 “폰을 만짐”을 가려 알람 대신 재안정화합니다.
- **자기 진동 차단** — 알람 진동 중에는 판정을 멈추고, 알람을 끄면 곧바로 다시 듣습니다.
- **웹 ↔ 안드로이드 일치** — 같은 입력에 대해 JS와 Java 판정기가 같은 결과를 내는지 골든 파일로 CI에서 검사합니다.

감시 안전장치: 찌를 20초 넘게 놓침, 영상이 4초 넘게 멈춤, 카메라 트랙 종료, 센서 신호 끊김, 화면 이탈 후 복귀를 모두 배너(+짧은 경고음)로 알립니다. 조용히 실패하지 않습니다.

## 백그라운드에 대한 정직한 안내

| 환경 | 화면이 켜져 있을 때 | 다른 앱·화면 꺼짐 |
| --- | --- | --- |
| 웹 / PWA | 카메라·진동 감시 | **멈춤**(돌아오면 알림). 무음 오디오 등으로 흉내 내지 않습니다 |
| 안드로이드 앱 | 카메라·진동 감시 | **진동 감시 계속** — 상태표시줄 “입질 감시 중” 알림(일시정지/종료) |
| iOS Safari | 시험 지원 | 지원한다고 표시하지 않습니다 |

안드로이드 앱의 백그라운드 감시는 사용자가 시작했을 때만 도는 foreground service(specialUse)이며, 재부팅 자동 시작·배터리 최적화 강제 해제·위치/마이크 권한 요청을 하지 않습니다. 12시간이 지나면 스스로 멈춥니다.

## 개인정보·보안

- 영상·센서 데이터는 저장하거나 전송하지 않습니다. 기록은 이 기기의 localStorage에만 남고, 내보내기는 사용자가 누를 때 로컬 JSON 파일로만 만듭니다.
- 배포 헤더(`vercel.json`): 엄격한 CSP(외부 스크립트·연결 차단), Permissions-Policy(카메라·가속도·자이로만 self), `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, COOP. E2E가 이 헤더를 그대로 적용한 서버에서 돌기 때문에 정책이 앱을 막으면 테스트가 실패합니다.

## 개발

Node 22 기준. 빌드 도구 없이 정적 파일 그대로 배포합니다.

```bash
cd jjibom-webapp
npm ci

npm test                 # 단위 테스트 (node --test)
npm run test:e2e         # 브라우저 E2E 전체 (UI · 실제 센서 경로 · 실제 카메라 경로)
npm run test:e2e:ui      #   화면 흐름만
npm run test:e2e:sensor  #   DeviceMotionEvent 경로(60/20 Hz, 중력만 주는 기기)
npm run test:e2e:camera  #   가짜 웹캠 영상으로 getUserMedia 경로

npm run build:web        # 정적 자산 → www/
npm run cap:sync         # www/ → android/ (Capacitor)
npm run golden           # 진동 판정 골든 파일 재생성 (Java 테스트가 사용)
npm run icons            # icons/icon.svg → PNG 아이콘
```

- E2E는 `playwright-core`로 Chromium을 띄웁니다. 브라우저 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다. 카메라 E2E는 합성 영상(y4m)을 OS 임시 폴더에 한 번 렌더링해 가짜 웹캠으로 재생합니다. 스크린샷은 `e2e/shots/`에 저장됩니다.
- 화면 문구에 새 한글을 넣었다면 글꼴 서브셋을 다시 만드세요(없는 글자는 `test/font.test.js`가 잡아냅니다):
  `pip install fonttools brotli` 후 `python3 scripts/subset-font.py <PretendardVariable.woff2 경로>`
- 안드로이드 빌드: JDK 21, Android SDK 36. `cd android && ./gradlew testDebugUnitTest assembleDebug`
- 서비스 워커 캐시는 `sw.js`의 `CACHE_VERSION`으로 관리합니다. 화면 자산을 바꿔 배포할 때 올려 주세요. 새 버전이 준비되면 앱 하단에 “새로고침” 배너가 뜹니다.

### CI

- **Web** (`.github/workflows/web.yml`): 단위 테스트 + 세 가지 E2E
- **Android APK** (`.github/workflows/android.yml`): 단위 테스트 → 골든 파일 일치 검사 → Capacitor 동기화 → Java 단위 테스트 → 디버그 APK 업로드

## 한계 (솔직하게)

- 폰·거치대가 계속 움직이면 흔들림 보류가 길어져 그 사이 입질을 놓칠 수 있습니다.
- 찌가 화면에서 너무 작거나(대략 8~12 px 미만) 배경·햇빛 반사와 색이 비슷하면 추적이 불안정합니다. 보정 단계에서 이유와 함께 거부합니다.
- 긴 시간 동안 해가 지거나 조명이 바뀌어 찌 색이 크게 달라지면 다시 선택해야 할 수 있습니다.
- 진동 감지는 거치 방식(커플러·거치대)과 낚싯대 탄성에 따라 민감도 조절이 필요합니다. 설정의 민감도 프리셋을 쓰세요.
- 실측(실제 낚시터) 데이터로 튜닝한 값이 아니라 합성 시나리오와 기기 시뮬레이션으로 검증한 값입니다. 현장 기록(내보내기 JSON)을 모아 재튜닝하는 것이 다음 단계입니다.
