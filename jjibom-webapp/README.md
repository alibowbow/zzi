# 찌봄 — 스마트폰 카메라 찌 감지 웹앱

스마트폰 카메라가 낚시찌를 계속 보고, 평소 물결보다 큰 움직임이 생기면 소리와 진동으로 알려주는 정적 웹앱입니다. 영상은 서버로 보내지 않고 **브라우저 안에서만** 처리합니다.

> 이 앱은 고전적인 컴퓨터 비전(색상 매칭 · 연결 요소 분석 · 블록 매칭)으로 동작합니다. 학습된 AI 모델을 사용하지 않으며, 그렇게 표시하지도 않습니다.

## 바로 실행하기

별도의 설치나 빌드가 필요 없습니다. (ES module을 쓰므로 `file://`가 아니라 로컬 서버로 열어야 합니다.)

```bash
cd jjibom-webapp
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 여세요.

- 카메라 없이 확인: **데모 체험** 버튼
- 실제 카메라 사용: **카메라 켜기** 버튼
- 휴대폰에서 실제 카메라를 쓰려면 HTTPS로 배포해야 합니다. (GitHub Pages, Netlify, Vercel 등 정적 호스팅에 폴더 그대로 올리면 됩니다.)

## 사용 순서

1. 휴대폰을 삼각대나 거치대에 단단히 고정합니다.
2. 카메라를 켭니다.
3. 화면에서 찌 끝의 빨강·주황·형광색 부분을 터치합니다.
4. 약 2~3초 동안 평소 물결을 보정합니다. (찌가 너무 작거나 흔들림이 크면 보정이 거부되고 이유를 알려줍니다.)
5. **감시 시작**을 누릅니다.
6. 잠김·급상승·반복 떨림이 감지되면 알람이 울립니다. 단순히 찌를 잠깐 놓친 경우에는 알람 대신 “찌를 놓쳤어요” 안내가 표시됩니다.

> **여러 찌 동시 감시:** 감지 설정에서 “여러 찌 동시 선택”을 켜면 화면을 여러 번 터치해 최대 4개의 찌를 각각 추적·감시할 수 있어요. 각 찌는 독립적으로 보정·판정되며, 어느 한 찌라도 입질이 감지되면 몇 번 찌인지와 함께 알람이 울립니다. 이미 선택한 찌 근처를 다시 터치하면 그 찌를 다시 지정하고, 단일 모드로 끄면 한 개만 추적합니다.

## 동작 방식 (개선된 추적·판정)

```text
카메라 프레임 (최대 약 320px로 축소)
→ 선택한 색과 가까운 픽셀로 색상 마스크 생성
→ 연결된 픽셀 덩어리(Blob)로 분리 — 흩어진 반사광은 합쳐지지 않음
→ 위치·색·크기·세로 길쭉함으로 찌 후보 점수화 후 선택
→ 배경 블록 매칭으로 카메라 전체 흔들림(dx,dy) 추정 후 제거
→ 찌 크기(찌 높이) 기준으로 이동량 정규화 → 줌/해상도에 둔감
→ 짧은 시간 구간의 움직임 패턴(잠김/급상승/떨림/파도)으로 입질 점수 계산
→ 추적 상태 머신으로 “입질”과 “추적 실패”를 분리
→ 신뢰도·흔들림·디바운스·쿨다운을 통과할 때만 알람
```

핵심 개선:

- **Blob 추적**: 색 평균이 아니라 연결 요소를 찾아, 떨어져 있는 같은 색 물체를 하나의 찌로 합치지 않습니다.
- **카메라 흔들림 보정**: 배경 패치 블록 매칭으로 전체 화면 이동량을 추정해 찌 이동에서 빼고, 흔들림이 크면 알람을 잠시 보류합니다.
- **크기 정규화**: 모든 임계값을 찌 높이의 배수로 계산해 줌·거리·해상도가 바뀌어도 민감도가 크게 달라지지 않습니다.
- **상태 머신**: `TRACKING / POSSIBLE_BITE / LOST / RECOVERING / ALARM` 등으로 나눠, 한두 프레임 놓침이 입질로 둔갑하지 않습니다.
- **패턴 분리**: 잠김(아래로 + 면적 감소), 급상승, 반복 떨림, 파도/바람을 구분해 점수화합니다.

## 파일 구성

```text
jjibom-webapp/
├── index.html              화면 구조
├── styles.css              모바일/데스크톱 디자인
├── app.js                  오케스트레이션 (DOM·분석 루프·데모 연결)
├── manifest.webmanifest    PWA 설치 정보
├── sw.js                   서비스 워커 (버전 캐시 + 전략별 페치)
├── package.json            Node 테스트 러너 설정 (type: module)
├── src/
│   ├── config.js           모든 튜닝 상수 (단위 주석 포함)
│   ├── stats.js            median, MAD, clamp 등 순수 통계
│   ├── color.js            색공간 변환 · 픽셀 매칭 · 대표색
│   ├── geometry.js         object-fit 좌표 변환 (터치 ↔ 분석 좌표)
│   ├── blobTracker.js      마스크 · 연결요소 · 후보 점수 · 신뢰도
│   ├── motionCompensation.js  배경 블록 매칭(흔들림 추정/보정)
│   ├── biteDetector.js     구간 패턴 분석 · 입질 점수 · 알람 게이트
│   ├── trackingState.js    추적 상태 머신 (순수 전이 함수)
│   ├── diagnostics.js      좌표 시계열 버퍼 · 이벤트 JSON 내보내기
│   ├── camera.js           카메라 수명주기 · 장치 선택 · 줌 · waitForVideo
│   ├── alarm.js            소리 · 진동 · Wake Lock (모두 방어적)
│   ├── storage.js          localStorage 폴백 · JSON 저장/내보내기
│   └── demo.js             가상 낚시터 (동일 추적 파이프라인 사용)
├── test/                   Node 내장 테스트 (브라우저 불필요)
└── icons/
```

계산 로직(`src/`의 순수 모듈)은 DOM/Canvas와 분리돼 있어 Node에서 그대로 테스트할 수 있습니다.

## 테스트

빌드 도구 없이 Node 내장 테스트 러너만 사용합니다. (Node 18+ 권장, 외부 의존성 없음)

```bash
cd jjibom-webapp
npm test          # 또는: node --test
```

테스트 항목: 색상 거리·매칭, Blob 분리/점수, 좌표 정규화(object-fit), 배경 이동 보정, 추적 신뢰도, 상태 머신 전이(짧은 놓침·흔들림이 입질로 처리되지 않음), 잠김 패턴 검출, 중복 알람 방지, 서비스 워커 캐시 버전 갱신 등.

## 개발 중 캐시 갱신

서비스 워커는 `sw.js`의 `CACHE_VERSION` 상수로 캐시를 관리합니다.

- 코드를 바꿔 배포할 때마다 `CACHE_VERSION`을 올리면 이전 캐시가 `activate` 단계에서 삭제됩니다.
- HTML/JS/CSS는 network-first 또는 stale-while-revalidate로 받으므로 온라인이면 최신 코드가 우선됩니다.
- 새 버전이 준비되면 화면 하단에 “새 버전이 준비됐어요 · 새로고침” 배너가 뜹니다.
- 로컬 개발 중 캐시가 헷갈리면 DevTools → Application → Service Workers → **Update on reload**를 켜거나, “Unregister” 후 새로고침하세요.

## 브라우저 지원

1차 지원 대상은 **안드로이드 Chrome**입니다. 기능별 가용성을 확인해 미지원 기능은 안전하게 우회합니다.

| 기능 | Android Chrome | iOS Safari |
| --- | --- | --- |
| 후면 카메라 / 전·후면 전환 | ✅ | ✅ |
| 카메라 장치 선택 | ✅ (복수 카메라 시) | 제한적 |
| 카메라 줌 슬라이더 | ✅ (지원 기기) | ❌ → 자동 숨김 |
| 소리 알람 (제스처 후 AudioContext) | ✅ | ✅ |
| 진동 알람 | ✅ | ❌ → 무시 |
| Wake Lock (화면 꺼짐 방지) | ✅ | ❌/제한 → 무시 |
| 서비스 워커 / 오프라인 / 설치 | ✅ | 부분 |

지원되지 않는 API는 UI에서 숨기거나 무시하며, 그 때문에 앱이 멈추지 않습니다. 화면이 백그라운드로 가면 카메라 분석이 멈출 수 있다고 안내합니다.

## 실전 사용 전에 알아둘 점

이 버전은 제품 검증용 MVP입니다. 다음 환경에서는 찌를 놓치거나 오탐이 생길 수 있습니다.

- 폰이나 거치대가 계속 움직이는 경우 (보정으로 줄이지만 한계가 있음)
- 찌가 화면에서 너무 작은 경우 (보정 단계에서 거부될 수 있음)
- 찌와 배경 물결의 색이 비슷한 경우
- 강한 햇빛 반사가 찌와 같은 색으로 보이는 경우
- 다른 낚싯줄/물체가 찌 앞을 자주 가리는 경우

처음에는 찌가 화면에서 최소 8~12px 이상 보이게 확대하고, 배경과 다른 밝은 찌 끝을 선택하세요.

## 현장에서 수집할 성능 지표

실측 데이터는 자동 전송하지 않습니다. 진단 패널에서 이벤트 JSON을 로컬로 내보내 직접 분석하세요. 측정 항목:

- 시간당 오탐 횟수
- 실제 입질 감지율
- 입질 후 알람 지연시간
- 추적 손실 횟수 / 추적 재획득 성공률
- 한 시간당 배터리 소모량
- 낮 · 밤(LED) · 햇빛 반사 · 잔잔한 물 · 강한 파도별 결과

## 다음 개발 권장 순서

1. 실제 낚시 영상 100~300개로 오탐 유형 분류 및 임계값 재튜닝

4. 입질 전후 저해상도 프레임의 선택적 로컬 저장
5. 여러 찌 동시 추적
6. 스마트워치·블루투스 알림 연동
7. 사용자별·찌 종류별 감지 프로필
